IN WENIGEN SCHRITTEN

Mit der App verbinden

  1. GET /api/v1 liefert Version, Ressourcen, Filter und Beziehungen.
  2. GET /api/v1/metadata liefert Chains, Adressarten, Zwecke, Börsenanbieter und CSV-Profile.
  3. Listen mit limit und offset laden und links.next bis null folgen. Einzelobjekte stehen unter data, Beziehungen unter data.links.
  4. Für Änderungen die dokumentierten Aktionsrouten nutzen. Synchronisierungen über POST /api/jobs/sync einreihen und den Jobstatus bis success oder error abfragen.

Buchungen einer Wallet laden

const response = await fetch(
  '/api/v1/transactions?wallet_id=1&limit=100'
);
const result = await response.json();
if (!response.ok) throw new Error(result.error);
for (const tx of result.data) {
  console.log(tx.amount, tx.asset, tx.links.wallet_id);
}
// Nächste Seite: result.links.next

Native App / Terminal

curl http://localhost:3000/api/v1

curl 'http://localhost:3000/api/v1/wallets?limit=100'

curl 'http://localhost:3000/api/v1/transactions/1'

curl 'http://localhost:3000/api/v1/price-audit?transaction_id=1'

Auf einem anderen Gerät bezeichnet localhost dieses Gerät. Dort die geschützte Adresse deiner CryptoBuch-Installation als Basis-URL verwenden.

Zugriff & Datenschutz

Die lokale API besitzt keine eigene Anmeldung und keine CORS-Freigabe. Browser-Apps benötigen dieselbe Origin oder einen Reverse Proxy. Externen Zugriff über einen authentifizierten HTTPS-Zugang schützen. Adressen und xPubs sind datenschutzsensibel; Provider-Schlüssel und Sitzungen bleiben aus der v1-Lese-API ausgeschlossen. Backup-Downloads können lokale Zugangsdaten enthalten.

Formate & Grenzen

JSON, EUR-Werte, Zeitstempel ohne Zeitzone in UTC. Ressourcen verwenden snake_case, bestehende Aktionen teilweise camelCase. Fehlende Werte bleiben null. Listen: 100 Einträge, maximal 500 pro Seite. Aufsteigend nach Primärschlüssel; mehrere Seiten sind kein unveränderlicher Snapshot. JSON-Body maximal 64 KiB, CSV maximal 2.500 Zeilen, Belege maximal 5 MiB.

Ergebnisse & Fehler

200 erfolgreich, 201 erstellt, 202 eingereiht, 204 ohne Inhalt. Fehler: {"error":"…"} mit 400 (Eingabe), 404 (unbekannt), 409 (Konflikt), 413 (zu groß) oder 500. Jobs bei 202 weiterverfolgen. Unbekannte v1-Filter werden abgelehnt.

Datenqualität & Geräte

Historische Werte, FIFO-Reports und Steuerplanungen sind unverbindliche Schätzungen und keine Steuerberatung. Manuelle Kurse und Zwecke bleiben geschützt. Die v1-Datenabrufe verwenden nur lokale Daten; Markt- und Portfolio-Routen können externe Kursanbieter benötigen. Ledger kommuniziert ausschließlich im Browser mit dem Gerät; nur bestätigte öffentliche Adressen speichern.

ABHÄNGIGKEITEN

So hängen die Daten zusammen

Jede Buchung gehört zu einer Wallet. Auch Börsenkonten sind Wallet-Quellen; ihre Zugangsdaten sind getrennt. Ein Transfer verbindet zwei Buchungen, Belege und Kurs-Audits beziehen sich jeweils auf eine Buchung. Direkte und rückwärtige Links ermöglichen die Navigation ohne Datenbankzugriff.
